# ВСХОД — сайт линейки микробиологических препаратов

Статический сайт бренда «ВСХОД» (розничная линейка INBIOLAB): каталог продуктов с отдельными SEO-страницами, раздел для бизнеса, страница о технологии и контакты.

- Стек: **Astro 7 + TypeScript**, без клиентских фреймворков. Единственный JavaScript на странице — мягкое появление секций (10 строк); меню, фильтр каталога и FAQ работают на чистом HTML/CSS.
- Контент продуктов: **Astro Content Collections**, JSON-файлы с типизированной схемой.
- Картинки: `astro:assets`, автоматически AVIF/WebP и `srcset`.
- Шрифт: Montserrat Variable, локально из `public/fonts`, preload кириллицы.
- Хостинг: **Vercel** (статика), переезд на любой хостинг = копирование папки `dist/`.

## Быстрый старт

```bash
npm install        # зависимости (Node ≥ 22.12)
npm run dev        # http://localhost:4321
npm run build      # production-сборка в dist/
npm run preview    # посмотреть dist/ локально
npm run check      # проверка типов и схем контента
npm run pending    # чек-лист «что добавить до публикации»
```

## Как добавить новый продукт

1. Положите фото сцены применения (и флакона, если есть) в `src/assets/scenes/`. Формат JPG/PNG, ширина от 1100 px.
2. Скопируйте любой файл из `src/content/products/`, например `gazon.json`, под новым именем. **Имя файла = адрес страницы**: `moy-product.json` → `/catalog/moy-product`. Используйте латиницу и дефисы; после публикации имя не менять.
3. Заполните поля. Обязательные: `order`, `name`, `tagline`, `description`, `accent`, `tags`, `image.scene`, `image.sceneAlt`, `seo`. Всё остальное можно опустить: блок без данных не выводится.
   - `accent` — один из `leaf | forest | teal | lilac | amber | sand | mint` (цвета направлений, `src/data/taxonomy.ts`).
   - `tags` — идентификаторы из `TAGS` в `src/data/taxonomy.ts`. Новую метку сначала добавьте туда.
   - `status: "coming"` — если паспорта ещё нет: страница будет короткой, без дозировок.
   - `usage.showSchedule: false` — скрыть таблицу регламента, если технолог его не подтвердил.
   - `image.focus` — точка фокуса кадра, например `"50% 70%"` (второе число: 0% верх, 100% низ). Портретные сцены обрезаются в карточке 4:3 и в шапке страницы, этим полем сдвигаете кадр, чтобы главный объект не срезался.
   - `image.page` — вторая сцена для шапки страницы продукта (в карточке остаётся `scene`). Необязательно.
   - `pending` — список того, чего не хватает; попадает в `npm run pending`, на сайт не выводится.
4. `npm run check` покажет ошибки схемы (например, слишком длинный `seo.title`). `npm run dev` — посмотреть.

Правило контента: **на сайт попадает только то, что есть в паспорте изделия.** Состав штаммов, титр, декларация, срок ожидания, результаты испытаний, цены, отзывы — не придумываются. Пока данных нет, поле остаётся пустым.

## Формы и персональные данные

На сайте **нет форм** и сбора персональных данных: все кнопки «Написать», «Запросить оптовое предложение», «Обсудить пилот» — это `mailto:` с подставленной темой письма и названием продукта, плюс ссылка на Telegram. Поэтому не нужны политика обработки ПДн, согласие, cookie-баннер, серверная часть и переменные окружения. `.env.example` описывает, что понадобится, если форму решат добавить позже.

Аналитика не подключена. Место для неё помечено комментарием в `src/layouts/Base.astro` (`<head>`), подключать после согласования политики cookies.

## Размещение

### Vercel (текущий вариант)

Проект статический, адаптер не нужен. Vercel определяет Astro автоматически: Framework Preset «Astro», Build Command `npm run build`, Output Directory `dist`. Каждый push в `main` на GitHub пересобирает сайт.

После подключения домена: поменять `site` в `astro.config.mjs` и `Sitemap` в `public/robots.txt`, сделать commit.

### Переезд на другой хостинг (Рег.ру, Timeweb, Яндекс Cloud и т. п.)

1. `npm run build` → папка `dist/` содержит готовый сайт (HTML, CSS, картинки, `sitemap-index.xml`).
2. Загрузить содержимое `dist/` в корень хостинга. Сервер должен отдавать `index.html` для `/` и файлы `*.html` для остальных адресов (каждая страница лежит в своей папке: `/catalog` → `catalog/index.html`). Для Apache/nginx это стандартно; на Рег.ру виртуальный хостинг подходит без Node.js.
3. Если появится форма с отправкой письма: логику вынести в отдельный модуль; на Node.js-хостинге это функция/эндпоинт с `nodemailer`, на PHP-хостинге — небольшой `mail.php`. Фронтенд формы от этого не меняется.
